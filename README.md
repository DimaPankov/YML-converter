# YML Студия · Kotlin Multiplatform Desktop

> Android и Desktop теперь подключены к общему проекту в родительской папке. Для работы с обеими платформами откройте `../settings.gradle.kts`; структура, команды сборки APK и инструкция находятся в [общем README](../README.md). Эта папка по-прежнему позволяет отдельно собирать Desktop. После добавления Android target Gradle также требует установленный Android SDK 36 (`ANDROID_HOME` либо `sdk.dir` в локальном `local.properties`).

Настольная программа на русском языке для подготовки YML-каталогов. Проект перенесён с Python/JavaScript на **Kotlin Multiplatform + Compose Multiplatform**. Windows и macOS используют общий JVM desktop target; модель проекта, проверка каталога и генерация XML находятся в `commonMain`.

Приложение работает в собственном окне, без Python, браузера и локального HTTP-сервера. Установщики включают Java runtime; пользователю не требуется устанавливать Java отдельно.

## Готовая сборка macOS

[Скачать YMLStudio 2.0.0 для Apple Silicon](dist/YMLStudio-2.0.0-macos-arm64.dmg). Откройте DMG и перенесите YMLStudio в Applications. Контрольная сумма находится рядом в `.sha256`.

Проверено на macOS: 25 тестов, включая UI-сценарий, сборка DMG и запуск приложения со встроенным runtime. Фактические сборка установщика и запуск на Windows, а также macOS Intel в этой среде не выполнялись.

## Запуск из Android Studio

1. Выберите **File → Open** и откройте корень `YML converter`, где находится `settings.gradle.kts`.
2. Дождитесь синхронизации Gradle. Если проект уже открыт, выполните **Sync Project with Gradle Files** или **Reload All Gradle Projects** в окне Gradle.
3. В списке конфигураций рядом с кнопкой Run выберите **YML Studio Desktop**.
4. Нажмите **▶ Run** — откроется desktop-окно приложения на вашем компьютере. Выбор эмулятора или телефона не требуется.

Конфигурация хранится в `.run/YML Studio Desktop.run.xml` и запускает `:composeApp:run`. Привязка проекта к Gradle также включена в проект. Используется Gradle Wrapper.

Для Gradle выбран **Embedded JDK** Android Studio (`#JAVA_INTERNAL`). Эта настройка не требует `java.home` в локальном `config.properties` и не содержит пути к конкретному компьютеру. Если IDE ещё показывает ошибку прежней настройки `GRADLE_LOCAL_JAVA_HOME`, нажмите **Use Embedded JDK** в сообщении или переоткройте проект, затем повторите синхронизацию. Для компиляции проекту нужен **JDK 17**: если он не установлен, добавьте его через **Settings → Build, Execution, Deployment → Build Tools → Gradle → Gradle JDK → Download JDK** и выберите версию 17. Эти настройки находятся в **Android Studio → Settings** на macOS.

Если конфигурация не появилась после синхронизации, переоткройте проект. Альтернативный запуск: окно **Gradle → composeApp → Tasks → compose desktop → run** или выполнение `:composeApp:run` через **Execute Gradle Task**.

## Запуск из исходников

Для разработки нужны **JDK 17** и интернет при первой сборке. Gradle Wrapper входит в проект. Откройте корневую папку в IntelliJ IDEA или Android Studio как Gradle-проект.

macOS:

```sh
./gradlew :composeApp:run
```

Windows PowerShell:

```powershell
.\gradlew.bat :composeApp:run
```

Либо запустите `start.command` / `start.bat`: при наличии собранного приложения скрипт открывает его, иначе запускает Gradle.

## Установщики

Сборка на macOS (архитектура приложения соответствует архитектуре JDK):

```sh
./gradlew :composeApp:desktopTest :composeApp:packageDmg
```

DMG: `composeApp/build/compose/binaries/main/dmg/`.
Приложение: `composeApp/build/compose/binaries/main/app/YMLStudio.app`.

Сборка на Windows x64, JDK 17 (для jpackage необходим WiX Toolset 3.x):

```powershell
.\gradlew.bat :composeApp:desktopTest :composeApp:packageMsi :composeApp:packageExe
```

Результат: `composeApp/build/compose/binaries/main/msi/` и `exe/`.
Установка для текущего пользователя; создаются ярлыки в меню и на рабочем столе.

Для сборки EXE из Android Studio / IntelliJ IDEA на Windows откройте папку
`YML converter`, выберите конфигурацию **YML Studio Windows EXE** и нажмите **▶ Run**.
Конфигурация `.run/YML Studio Windows EXE.run.xml` выполняет `:composeApp:packageExe`;
готовый установщик появится в `composeApp/build/compose/binaries/main/exe/`.
Нужны JDK 17 с `jpackage`, Android SDK 36 и WiX Toolset 3.x.
Если встроенная Java IDE не содержит `jpackage`, добавьте в параметры конфигурации
`-PdesktopJavaHome="C:\\путь\\к\\jdk-17"`, указав путь к полному JDK.
Эту конфигурацию следует запускать на Windows.

EXE/MSI собираются на Windows, DMG — на macOS, как описано в [документации Compose](https://kotlinlang.org/docs/multiplatform/compose-native-distribution.html). В `.github/workflows/desktop.yml` настроены тесты и сборки Windows x64, macOS Apple Silicon и macOS Intel с загрузкой установщиков в artifacts. Workflow нужно запустить в GitHub-репозитории; наличие конфигурации не означает, что Windows-сборка уже проверена. Подпись и notarization не настроены.

**Старый `dist/YML-Studio-Setup-1.0.0-x64.exe` относится к Python-версии, это не новый Kotlin-установщик.**

### Сборка Windows через GitHub Actions

Отправьте актуальные изменения в GitHub и откройте **Actions → Desktop builds**.
Сборка запускается при push; вручную её можно запустить через **Run workflow**.
После успешного задания Windows скачайте архив **YMLStudio-windows-x64** из
раздела **Artifacts** на странице запуска: внутри находятся EXE и MSI.

Если упаковка завершится ошибкой, откройте шаг **Show Windows packaging diagnostics**
или скачайте **packaging-diagnostics-windows-x64**. Там сохраняются журналы
`jpackage` и файлы его аргументов. Windows-сборка передаёт `JAVA_TOOL_OPTIONS=-Dfile.encoding=UTF-8`
дочерним Java-процессам, чтобы они читали аргументы с кириллицей в той же кодировке,
в которой их записывает Gradle. После изменения workflow запускайте сборку нового
коммита: **Re-run jobs** у старого запуска использует прежнюю конфигурацию.

## Возможности

- Создание, редактирование, поиск и удаление товаров, фильтр по форме; неполные карточки сохраняются как черновики.
- Конструктор форм: копирование, поля YML и характеристики `param`, типы данных, обязательность, единицы, значения по умолчанию, порядок полей. Форму, используемую товарами, удалить нельзя.
- Настройки магазина, НДС, категории и их иерархия.
- JPEG/PNG до 15 МБ, 250–3500 пикселей по каждой стороне, локальные превью, публичные ссылки, порядок фотографий. Первое фото основное; максимум 10.
- Проверка цен, дат, артикулов, категорий, обязательных полей, четырёх характеристик, ссылок и XML-символов.
- UTF-8 YML и ZIP с `catalog.yml` и `images/`.
- Атомарное сохранение `project.json`, резервные ZIP-копии, импорт проекта из предыдущей версии, предупреждение о несохранённых изменениях.
- Блокировка рабочего каталога от одновременной записи двумя экземплярами новой версии.

## Как пользоваться

1. Откройте **Настройки каталога**, заполните магазин, компанию и категории, нажмите **Сохранить**.
2. При необходимости настройте шаблон в **Конструкторе форм**.
3. В **Товарах** нажмите **Добавить товар**, выберите форму, заполните поля и добавьте фото. Дата вводится как `2026-09-08T12:00`. Сохраните карточку.
4. В **Экспорте YML** исправьте ошибки и сохраните YML или ZIP.
5. Разместите содержимое `images/` по публичному адресу из настроек, сохранив имена файлов, затем импортируйте YML на портал. Программа не публикует фотографии самостоятельно.

Ссылки на удалённые фото не загружаются для проверки или превью. Их доступность, формат и размеры проверяются пользователем. Отдельная ссылка фотографии имеет приоритет над адресом папки.

Перенесены правила исходного проекта, основанные на предоставленной инструкции 2025 года. Это не обновление требований портала: полная XSD-валидация и проверка кодов по актуальным справочникам не реализованы. НДС вводится пользователем при включённой передаче ставок. Специальные типы предложений, акции и тарифы доставки не реализованы. Окончательная проверка выполняется порталом при импорте.

## Данные и переход со старой версии

### Загрузка товаров и форм из YML

- В разделе **Товары** нажмите **Загрузить товары из YML**, выберите файл и подтвердите
  добавление. Создадутся новые товары; для каждого набора полей будет использована
  совпадающая существующая форма или создана новая. Существующие товары
  и настройки магазина сохранятся; пустые, некорректные и совпадающие артикулы заменятся случайными уникальными.
- В **Конструкторе форм** нажмите **Загрузить форму из YML**. Укажите название формы
  и выберите набор полей, если файл содержит несколько разных форм. Товары с одинаковыми
  полями объединяются; при одной форме список выбора не показывается. Значения первого товара группы станут
  значениями по умолчанию, а ссылки на фото будут добавляться в новые карточки.
  Артикул каждой новой карточки назначается автоматически. После импорта открывается
  редактор формы, где можно изменить значения и убрать фотографии.
- Поддерживается XML-файл YML с каталогом `yml_catalog`, списком `offers` или отдельным
  `offer`, до 10 МБ и 10 000 товаров. Импортируются обычные поля, характеристики `param`
  с единицами, ссылки на фотографии, регионы и один вариант доставки. Фото по ссылкам
  автоматически не скачиваются. Перед добавлением показываются предупреждения о
  неподдерживаемых полях. Несколько вариантов доставки в одном товаре требуют
  предварительного выбора одного варианта в исходном файле.
- Для редактирования и дальнейшей выгрузки импортированного НДС включите передачу
  НДС в настройках каталога. Перед экспортом проверьте импортированные карточки.

### Быстрый доступ при копировании

Откройте форму в **Конструкторе форм**, отметьте у нужных полей
**Быстрый доступ при копировании товара** и сохраните форму. Например, отметьте цену,
размер и цвет. При нажатии **Копировать** у товара эти поля появятся рядом с названием:
можно сразу изменить значения и сохранить копию. Списки и выбор даты работают так же,
как в карточке товара. Название доступно всегда, артикул копии назначается автоматически;
если артикул включён в быстрый доступ, можно задать свой уникальный артикул.
Остальные значения и фотографии копируются. **Отмена** не создаёт товар.

### Изменение формы существующих товаров

После сохранения формы её поля, порядок, подписи, обязательность, списки и быстрый доступ
обновляются у всех связанных товаров, а также у форм с полностью совпадающей структурой
и их товаров. Совпадение определяется **до редактирования** по полям YML, типам данных,
названиям характеристик и единицам; порядок, внутренние ID и значения товаров не учитываются.
Это позволяет синхронно добавлять, удалять и переименовывать поля даже у форм из разных импортов.

Введённые значения и фотографии товаров сохраняются. Новое поле получает значение
по умолчанию; изменение значения по умолчанию существующего поля влияет на новые карточки.

### Срок доставки в старых формах

При открытии проекта и импорте YML программа распознаёт характеристику `param`
с названием **Срок доставки, рабочие дни**. Если настоящее поле `deliveryDays` пустое,
корректное однозначное значение из характеристики переносится в него. В YML срок
передаётся как `delivery-options/option/@days`. Полностью совпадающее дублирующее поле
убирается из формы. Различающиеся или некорректные значения сохраняются для проверки;
уже заполненный срок доставки автоматически не заменяется. При обычном сохранении
восстановленные данные записываются в проект.

### Формирование артикула

При создании и копировании товара автоматически генерируется случайный артикул из
12 заглавных латинских букв и цифр, например `7K3MX9R5AW2H`. Символы `0`, `O`, `1`, `I`
исключены, чтобы их было легче различать. Генератор проверяет уникальность во всём
каталоге независимо от формы, без учёта регистра; при совпадении повторяет выбор.
Артикул сохраняется вместе с товаром и не меняется при редактировании или экспорте.

При импорте корректные неповторяющиеся артикулы сохраняются. Для пустых, некорректных
и повторяющихся используется тот же генератор; учитываются также другие строки файла.
Ручной артикул должен соответствовать правилу проекта: 1–20 латинских букв и цифр,
без пробелов и дефисов.

### Светлая и тёмная тема

В **Настройках каталога → Оформление** выберите **Светлая** или **Тёмная**.
Тема применяется сразу; нажмите **Сохранить**, чтобы она восстановилась после запуска.
Также переключатель **Светлая тема / Тёмная тема** доступен внизу боковой панели
из любого раздела. Он сохраняет выбор автоматически, не сохраняя и не отменяя
несохранённые правки в карточке или форме.
Оформление применяется к разделам, карточкам, спискам и диалогам приложения.

### Массовое изменение и удаление товаров

В разделе **Товары** нажмите правую кнопку мыши на карточке. В контекстном меню
доступны **Выбрать товар**, **Изменить**, **Копировать** и **Удалить**; постоянно на карточке
кнопки и флажки не показываются. Без выбранных товаров обычный клик открывает карточку
для редактирования. После выбора первого товара обычный клик отмечает следующие
товары той же формы или снимает с них выбор. Выбранные карточки подсвечиваются.
Товары других форм в этом режиме выбрать нельзя. После снятия всего выбора обычный
клик снова открывает редактор.
Кнопка **Выбрать все этой формы** отмечает все товары этой формы в текущем результате
поиска. При изменении поиска, фильтра или переходе в другой раздел выбор сбрасывается.

Справа вверху появятся **Удалить** и **Изменить**. Удаление применяется сразу к выбранным
товарам. В окне изменения (примерно две трети окна приложения) отметьте поля, укажите
общие значения и нажмите **Применить**. Неотмеченные поля сохраняются; отмеченное поле
с пустым значением очищается. Кнопка **Сгенерировать** напротив поля **Артикул** заменяет артикулы
выбранных товаров случайными значениями из 12 латинских букв и цифр. Новые артикулы
не повторяются между собой и не совпадают с существующими в каталоге. Изменения
сохраняются только после нажатия **Применить**. Фотографии остаются индивидуальными.
Неполные карточки можно сохранять как черновики, как при обычном редактировании.

### Хранение проектов

- Windows: `%LOCALAPPDATA%\YMLStudio\data` — тот же путь, что у старого установленного приложения.
- macOS: `~/Library/Application Support/YMLStudio/data`.
- В папке находятся `project.json`, `images/` и служебная блокировка.
- Для отдельного каталога задайте `YML_STUDIO_DATA_DIR` или передайте собранному приложению `--data-dir /путь/к/папке`.

Перед переходом завершите старую Python-программу: она не использует новую файловую блокировку. На Windows сохранённый проект установленной версии открывается автоматически. На macOS или при переносе с другого компьютера выберите **Настройки → Импорт project.json**. Рядом с выбранным JSON должна находиться его папка `images/`.

Импорт проверяет структуру и наличие фотографий, создаёт в текущей папке данных `backup-before-import-<время>.zip`, копирует фотографии под новыми именами и сохраняет каталог. Исходный проект не изменяется. Несохранённые правки текущего каталога при подтверждённом импорте отменяются.

Для резервного копирования нажмите **Резервная копия ZIP** в настройках. Копия содержит только сохранённый проект и все локальные фотографии, в том числе ранее удалённые из карточек. Для восстановления распакуйте ZIP в отдельную папку и импортируйте её `project.json`. Данные при обновлении приложения сохраняются отдельно от установки.

Повреждённый проект не заменяется пустым автоматически: приложение показывает ошибку открытия. Восстановите `project.json` из копии либо запустите программу с отдельной папкой данных.

## Структура и проверки

- `composeApp/src/commonMain` — совместимая JSON-модель, правила каталога и экспорт XML.
- `composeApp/src/desktopMain` — Compose UI, файловое хранилище, ZIP, ImageIO, платформенные функции.
- `composeApp/src/commonTest` — проверки правил каталога.
- `composeApp/src/desktopTest` — совместимость с эталонным экспортом Python, хранение, блокировка, импорт, изображения, UI-сценарий.
- `legacy/` — архив исходной Python/web-версии для сравнения. Новое приложение его не использует.

```sh
./gradlew :composeApp:desktopTest
./gradlew :composeApp:createDistributable
```

Отчёт: `composeApp/build/reports/tests/desktopTest/index.html`. UI-тест требует графической сессии. Собранное приложение поддерживает `--smoke-test --data-dir <временная папка>` для проверки запуска со встроенным runtime без открытия окна.
