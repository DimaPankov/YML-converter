# YML Студия

Локальная программа на русском языке для подготовки YML прайс-листов Портала поставщиков Москвы по переданной инструкции 2025 года. YML здесь — XML (Yandex Markup Language).

## Установка на Windows

Готовый установщик: [`dist/YML-Studio-Setup-1.0.0-x64.exe`](dist/YML-Studio-Setup-1.0.0-x64.exe).

Поддерживаемая целевая система — Windows 10/11 x64. Запустите EXE, завершите установку и откройте ярлык **YML Студия** на рабочем столе или в меню «Пуск». Python включён в установщик, отдельно устанавливать его не нужно. Установка работает без интернета.

Интерфейс открывается в отдельном окне установленного Microsoft Edge или Google Chrome; при их отсутствии используется браузер по умолчанию. Программа устанавливается для текущего пользователя в `%LOCALAPPDATA%\Programs\YMLStudio`. Рабочие данные находятся отдельно: `%LOCALAPPDATA%\YMLStudio\data`. Обновление и удаление приложения сохраняют эту папку.

Для немедленного завершения нажмите **Завершить работу** в правом верхнем углу. После простого закрытия окна локальный процесс автоматически завершится примерно через 10 минут. При повторном запуске используется уже работающий экземпляр.

Перед обновлением сохраните изменения и завершите программу. Удаление доступно через «Параметры Windows → Приложения → YML Студия» или меню «Пуск». Установщик не подписан сертификатом издателя.

Подробная инструкция: [`dist/Инструкция Windows.txt`](dist/Инструкция%20Windows.txt). Журнал ошибок: `%LOCALAPPDATA%\YMLStudio\application.log`.

Сборка выполнена NSIS на macOS. Проверены Python-код, API настольной оболочки и состав установщика. Фактические установка, запуск ярлыка и удаление на Windows ещё не проверены.

### Повторная сборка установщика

Нужны NSIS (`makensis`) и официальный встраиваемый Python 3.13.13 x64. Исходный архив загрузки и его SHA-256 записываются в `build/windows/payload/build-manifest.json`.

```sh
curl -fL -o build/downloads/python-3.13.13-embed-amd64.zip https://www.python.org/ftp/python/3.13.13/python-3.13.13-embed-amd64.zip
python3 packaging/windows/build.py
```

Использованы [встраиваемый дистрибутив Python](https://docs.python.org/3.13/using/windows.html#windows-embeddable) и [NSIS](https://nsis.sourceforge.io/Docs/). Лицензия Python включена в `runtime/LICENSE.txt` установленной программы.

## Запуск

Нужен Python 3.10 или новее. Дополнительные библиотеки для приложения не нужны.

```sh
python3 server.py
```

Откройте http://127.0.0.1:8765. На macOS можно запустить `start.command` двойным щелчком, затем открыть этот адрес. Чтобы остановить сервер, нажмите Ctrl+C в его терминале.

Если порт занят:

```sh
python3 server.py --port 8767
```

## Как пользоваться

1. В **Настройках каталога** заполните название магазина, компанию и категории. Сохраните настройки.
2. В **Конструкторе форм** отредактируйте универсальную форму или создайте свою. Полям можно менять названия, порядок, обязательность и значения по умолчанию. Для своих характеристик выберите `Характеристика (param)`, тип данных и при необходимости единицу измерения. Сохраните форму.
3. В **Товарах** нажмите **Добавить товар**, выберите сохранённую форму и заполните поля. При необходимости загрузите фотографии или добавьте ссылки. Сохраните товар. Неполные карточки можно сохранять как черновики.
4. В **Экспорте YML** исправьте показанные ошибки. Скачайте `.yml` или ZIP с YML и загруженными фотографиями.
5. Разместите фотографии по публичным адресам и загрузите YML в раздел массового импорта Портала поставщиков.

Изменения сохраняются кнопками «Сохранить». При уходе из редактора с несохранёнными изменениями приложение предупреждает об этом. Формы можно выбирать, копировать, редактировать и удалять. Форма, используемая товарами, защищена от удаления: сначала удалите связанные товары. Изменение формы влияет на отображение и экспорт всех её товаров. Значения по умолчанию применяются при создании новых карточек.

Один экземпляр приложения рассчитан на работу одного пользователя в одной вкладке. Одновременное редактирование в нескольких вкладках может перезаписать более ранние изменения.

## Фотографии

По PDF, стр. 23 и 37–38:

- JPEG или PNG, от 1 до 10 изображений на предложение; первое — основное.
- От 250 до 3500 пикселей по каждой стороне; рекомендовано от 600 пикселей по меньшей стороне.
- В `<picture>` передаётся абсолютная публичная HTTP/HTTPS-ссылка длиной не более 512 символов. Кириллица допустима.
- Ссылка должна вести прямо на изображение, а не на HTML-страницу. Base64 и локальные файловые пути не подходят.
- Изображение должно соответствовать товару; нельзя добавлять рекламные надписи, цены и контакты. Водяные знаки — не более 10% площади. Основное фото должно показывать товар целиком.

Приложение проверяет формат и размеры загруженных файлов. Дополнительный лимит приложения — 15 МБ на фотографию. Содержимое и размеры удалённых изображений по ссылкам автоматически не проверяются. Приложение не размещает изображения в интернете.

Для файлов укажите в настройках, например, `https://example.ru/images`. Архив содержит `catalog.yml` и папку `images/`. Загрузите **содержимое** этой папки в публичную папку `https://example.ru/images/`, сохранив имена. Можно также задать отдельный URL для конкретной фотографии — он имеет приоритет над общим адресом.

## Правила экспорта и ограничения

- UTF-8, дата генерации `YYYY-MM-DD hh:mm`, namespace `http://market.zakupki.mos.ru/spIntegration/Yml/1.0`.
- `shop`, `categories`, `offers` — соседние элементы корня согласно примеру на стр. 26 PDF.
- Валюта RUB, курс 1. Цена с запятой преобразуется в число с точкой.
- Проверяются обязательные поля, уникальность артикулов, категории и их иерархия, даты, цены, ссылки и допустимые XML-символы.
- Принято требование минимум 4 заполненных `<param>` со стр. 16. Модель и производитель в это число не входят. На стр. 24 ограничение количества изложено иначе; здесь используется более строгое правило.
- НДС включается отдельно в настройках. Значение `vat` необходимо брать из актуального справочника портала. Программа не подставляет предполагаемые значения НДС.
- Код страны ОКСМ, ID категорий портала, СТЕ, регионов, упаковки и единиц измерения вводятся пользователем по справочникам портала. Наличие кодов в справочниках автоматически не проверяется.
- Поддерживается основная товарная форма и перечисленные в конструкторе дополнительные поля. Специальные типы предложений для книг, билетов, туров, акции и тарифы доставки не реализованы.
- В PDF есть противоречия между таблицами и примерами. Проверка обязательности опирается на подробную таблицу стр. 14–17; НДС обязателен при включённой передаче ставок, категория поставщика может заменяться `ppCategory`.
- Полная XSD-валидация не реализована: схему по ссылке из PDF получить не удалось. Проверка в программе не гарантирует принятие порталом; окончательная проверка выполняется при импорте. Для расширения проверки понадобится актуальная XSD со всеми зависимостями из личного кабинета.

## Хранение и резервная копия

Данные хранятся в `data/project.json`, фотографии — в `data/images/`. Не удаляйте эту папку. Запись проекта атомарная: невалидная структура не заменяет сохранённый проект.

В настройках можно скачать ZIP резервной копии с проектом и фотографиями. Копия включает только сохранённые изменения. Для восстановления остановите сервер, сохраните текущую папку `data` в другом месте и распакуйте содержимое резервной копии в `data`: файл `project.json` должен лежать непосредственно в `data`, каталог `images` — внутри неё. Перезапустите приложение.

При удалении товаров фотографии физически не удаляются, чтобы сохранить возможность восстановить ссылки и не повредить другие карточки. Поэтому резервная копия включает также ранее загруженные файлы.

Сервер слушает только `127.0.0.1`. Пользовательские данные не отправляются сторонним сервисам; отображение фото по внешнему URL выполняет обычный запрос браузера к этому адресу.

## Проверки

```sh
python3 -m unittest discover -s tests -v
node --check static/app.js
```

В `tests/browser.cjs` находится дополнительный сценарий проверки интерфейса через Playwright и установленный Google Chrome. Он рассчитан на отдельный сервер на порту 8766 с пустой тестовой папкой данных; Playwright устанавливается отдельно в `/tmp/yml-ui-test`. Рабочая база в проверках интерфейса не используется.
